# Demonic Room GUI Implementation Plan

**Goal:** Add Legacy-inspired, resizable Denizens, Items, and Players panels to Demonic.

**Architecture:** A dedicated Lua UI module uses bundled Geyser/Adjustable widgets and the existing authoritative room roster. Player tracking extends room state. No Legacy dependency, new hunting controller, or polling loop.

**Approved design:** Three independent panels in a left-side stack; charcoal/crimson/violet theme, gold allowlisted denizens, cyan players, green items; duplicate denizens grouped with counts and ID-specific target menus. Players select existing player targeting; items offer Get/Probe; denizens can be added to the current area's hunt list. Geometry and visibility persist per profile; demui show/hide/reset controls.

## Tasks

1. Add behavior tests for players, room invalidation, grouped display, exact-ID/stale callbacks, passive refresh, lifecycle and persistence. Watch failures before implementing.
2. Extend room state with name/players/playersReady and GMCP handlers; publish accepted room changes and retirement/list changes without altering Hunt readiness or refresh budgets.
3. Implement guarded GUI lifecycle, rendering, menus, persistence and aliases. Initialize before cached-room hydration, retry on sysLoadEvent, destroy owned widgets on shutdown.
4. Bundle GUI before final bootstrap, update metadata/docs and embedded-script verification; rebuild and run the complete suite, Lua syntax and XML synchronization checks.

## Constraints and acceptance

- Lua 5.1-compatible; only dem is global; names are literal text, callbacks are functions and item commands use validated numeric IDs.
- Current Room.Info remains identity authority. Clear old contents immediately; preserve valid same-room/background snapshots. Separate waiting, empty and disconnected states.
- Passive UI requests send once through room.request, with no text fallback/retries; active Hunt retains existing shared budgets. GUI cannot grant readiness.
- Check owner, room context and current membership in every action. UI/persistence errors cannot interrupt Hunt. Preserve existing settings and unrelated untracked mapper.
- Test player List/Add/Remove, self exclusion, duplicate counts, protection/corpses, target marker, stale callbacks, source bundling, headless operation and repeated reload cleanup.
- Live drag/resize and live Imperian packet ordering remain separate from simulated unit tests.

## Approaches

Independent panels were selected over one stacked or tabbed panel because each can be positioned/resized separately like Legacy. Native Mudlet widgets share room state rather than importing Legacy and its name database.
